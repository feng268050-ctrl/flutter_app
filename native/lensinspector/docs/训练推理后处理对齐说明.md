# YOLOv8 P2/P3/P4 训练、推理与后处理对齐说明

更新时间：`2026-05-22`

## 1. 任务与类别

- 任务类型：目标检测
- 数据集配置：`ultralytics/cfg/datasets/lens.yaml`
- 类别数：`nc = 1`
- 类别名：

```yaml
0: contamination
```

## 2. 训练模型结构

训练使用普通 YOLOv8 Detect 头，不使用 YOLOE prompt 检测头。

- 模型配置：`ultralytics/cfg/models/v8/yolov8-p2p3p4.yaml`
- 检测头：`Detect`
- 检测层：P2 / P3 / P4
- stride：`[4, 8, 16]`
- 输入尺寸：`640 x 640`

对应特征图尺寸：


| 层级  | stride | 特征图尺寸       | anchor 点数 |
| --- | ------ | ----------- | --------- |
| P2  | 4      | `160 x 160` | 25600     |
| P3  | 8      | `80 x 80`   | 6400      |
| P4  | 16     | `40 x 40`   | 1600      |
| 合计  | -      | -           | 33600     |


## 3. 训练参数

训练入口：`yolov8_demo.py`

关键参数：

```python
imgsz = 640
batch = 32
epochs = 300
patience = 30
optimizer = "AdamW"
lr0 = 0.01
lrf = 0.01
weight_decay = 0.0005
warmup_epochs = 3.0
cos_lr = True
label_smoothing = 0.01
box = 7.5
cls = 0.5
dfl = 1.5
```

数据增强：

```python
mosaic = 0.5
close_mosaic = 20
mixup = 0.0
copy_paste = 0.0
degrees = 5
translate = 0.05
scale = 0.3
shear = 0.0
perspective = 0.0
fliplr = 0.3
flipud = 0.0
hsv_h = 0.01
hsv_s = 0.3
hsv_v = 0.2
multi_scale = True
rect = False
```

训练数据不是直接使用完整 `1920 x 1080` 原帧训练，而是先离线从原帧固定裁剪 ROI，再 resize 为 `640 x 640` 图片输入 YOLOv8 训练流程。

因此模型实际学习到的视野是：

```text
1920 x 1080 原帧
-> 固定裁剪 ROI: x=565, y=110, w=700, h=700
-> resize 到 640 x 640
-> 作为训练图片 / 推理输入
```

当前固定圆心与裁剪参数为：

```text
center_x = 885.0
center_y = 430.0
crop_x = 565
crop_y = 110
crop_w = 700
crop_h = 700
resize_to = 640
```

注意：这里不是以 `(885, 430)` 为几何中心裁 `700 x 700`。实际 ROI 左上角固定为 `(565, 110)`，圆心在 ROI 内部坐标为：

```text
circle_x_in_crop = center_x - crop_x = 320
circle_y_in_crop = center_y - crop_y = 320
```

这样做的目的是让 `700 x 700` ROI 更完整覆盖圆形检测区域，再缩放到模型输入尺寸。

训练阶段不是把完整 `1920 x 1080` 原帧强行拉伸到 `640 x 640`。

Ultralytics YOLOv8 检测训练的数据管线会使用 `LetterBox(new_shape=(imgsz, imgsz))`，即：

```text
按原图比例缩放
不足部分 padding 到 640 x 640
同步更新 bbox 坐标
```

因为当前：

```python
imgsz = 640
rect = False
```

由于离线裁剪后的训练图片已经 resize 成 `640 x 640`，常规单图训练路径中的 letterbox 基本不会产生额外缩放和 padding：

```text
letterbox_gain = 1
pad_x = 0
pad_y = 0
```

部署推理侧必须复现同样的固定 ROI 裁剪和 resize 逻辑，不能直接把完整 `1920 x 1080` 原帧 resize 或 letterbox 到 `640 x 640`，否则视野范围、目标尺度和背景分布都会与训练不一致。

训练阶段还启用了以下图像增强：

```text
mosaic        = 0.5
degrees       = 5
translate     = 0.05
scale         = 0.3
fliplr        = 0.3
hsv_h/s/v     = 0.01 / 0.3 / 0.2
multi_scale   = True
```

含义：

1. `mosaic = 0.5`：约 50% 概率使用 mosaic 拼图增强。
2. `close_mosaic = 20`：最后 20 个 epoch 关闭 mosaic，让模型回到更接近真实单图的训练分布。
3. `degrees = 5`：允许小角度旋转。
4. `translate = 0.05`：允许小幅平移。
5. `scale = 0.3`：允许随机缩放。
6. `fliplr = 0.3`：约 30% 概率水平翻转。
7. `hsv_h/s/v`：颜色空间增强。
8. `multi_scale = True`：训练 batch 进入模型前还会随机缩放输入尺寸，并对齐 stride。

因此训练侧的图像处理可以概括为：

```text
1920 x 1080 原帧离线固定裁剪 700 x 700 ROI
-> resize 到 640 x 640 训练图
-> 读取 640 x 640 训练图
-> 按需 mosaic / 随机几何增强 / HSV / flip
-> letterbox 到训练输入尺寸
-> 归一化到 0~1
-> multi-scale 时再随机缩放 batch 输入
```

部署侧不需要复现训练时的随机增强，例如 mosaic、旋转、平移、HSV、flip；但必须复现确定性的推理预处理：

```text
1920 x 1080 原帧固定裁剪 ROI: x=565, y=110, w=700, h=700
resize 到 640 x 640
BGR/RGB 顺序与模型输入保持一致
letterbox 到 640 x 640（当前 resize 后已是 640 x 640，实际 gain=1、pad=0）
除以 255 归一化
NCHW 排列
```

## 4. 预训练权重处理

当前流程：

1. 先用 `yolov8-p2p3p4.yaml` 构建新模型结构。
2. 再加载 `yolov8n.pt` 迁移可匹配的预训练权重。
3. 不直接用旧架构 `best.pt` 初始化新模型。

原因：

- 新模型检测层是 P2/P3/P4。
- 旧 YOLOv8 默认检测层通常是 P3/P4/P5。
- 检测头结构不同，直接加载旧 `best.pt` 作为模型会造成结构不一致。
- 迁移 `yolov8n.pt` 时，能匹配的 backbone 和部分 head 权重会被加载，不能匹配的层会重新初始化。

## 5. 训练阶段 raw 输出张量

训练 loss 使用的是未解码 raw head 输出。

因为：

- `reg_max = 16`
- bbox DFL 通道数：`4 * reg_max = 64`
- 类别数：`nc = 1`
- 每个 anchor 输出通道数：`64 + 1 = 65`

所以训练 raw 输出为 3 个 tensor：


| 层级  | shape               |
| --- | ------------------- |
| P2  | `[B, 65, 160, 160]` |
| P3  | `[B, 65, 80, 80]`   |
| P4  | `[B, 65, 40, 40]`   |


如果 `batch = 32`，则为：

```text
P2: [32, 65, 160, 160]
P3: [32, 65, 80, 80]
P4: [32, 65, 40, 40]
```

loss 内部会 reshape 并拼接为：

```text
[B, 65, 33600]
```

其中：

```text
33600 = 160*160 + 80*80 + 40*40
```

## 6. PyTorch 推理输出

使用 `YOLO(best.pt).predict(...)` 时，Ultralytics 内部会完成：

1. DFL 解码
2. anchor/stride 还原
3. sigmoid 分类分数
4. NMS

因此 Python 推理脚本里拿到的 `result.boxes` 已经是后处理结果：

```text
result.boxes.xyxy   # [N, 4]
result.boxes.conf   # [N]
result.boxes.cls    # [N]
```

当前推理脚本已显式对齐训练输入尺寸：

```python
imgsz = 640
conf = 0.25
iou = 0.35
```

## 7. ONNX / RKNN 输出张量

当前检测导出脚本：

```python
model.export(
    format="onnx",
    imgsz=640,
    nms=False,
    dynamic=False,
)
```

注意：`nms=False` 表示不导出 NMS，但 Ultralytics `Detect` 导出时通常已经包含 DFL decode。

因此导出的单输出 tensor 预期为：

```text
[1, 5, 33600]
```

含义：

```text
5 = 4 + nc = 4 + 1
```

通道含义通常为：

```text
output[0, 0, :] = cx
output[0, 1, :] = cy
output[0, 2, :] = w
output[0, 3, :] = h
output[0, 4, :] = class0_score
```

坐标是基于 `640 x 640` 输入尺度的像素坐标。

`det_no_postprocess.onnx` 的含义是：模型图里没有最终 NMS 后处理，但这里的标准 Ultralytics ONNX 输出通常已经完成了 DFL bbox decode。

因此部署侧需要手写的是 **阈值过滤、坐标格式转换、NMS、坐标还原**，不需要再手写 DFL decode。

### 7.1 `det_no_postprocess.onnx` 后处理步骤

部署前处理应先从原始 `1920 x 1080` 帧固定裁剪 `700 x 700` ROI，再 resize 到 `640 x 640`：

```text
center_x = 885.0
center_y = 430.0
crop_x = 565
crop_y = 110
crop_w = 700
crop_h = 700
resize_to = 640
```

然后将 resize 后的 `640 x 640` 图送入模型。当前模型输入已经是 `640 x 640`，letterbox 实际为 no-op：

```text
letterbox_gain = 1
pad_x = 0
pad_y = 0
```

因为当前 ROI 是 `700 x 700` resize 到 `640 x 640`，后处理还原到原始 ROI 时需要保存 resize 比例：

```text
resize_gain = 640 / 700
roi_restore_scale = 700 / 640
```

ONNX 输出按 `[1, 5, 33600]` 处理：

```text
cx    = output[0, 0, i]
cy    = output[0, 1, i]
w     = output[0, 2, i]
h     = output[0, 3, i]
score = output[0, 4, i]
cls   = 0
```

因为当前模型只有 1 类 `contamination`，所以：

```text
class_id = 0
confidence = class0_score
```

不要按 COCO 80 类去取最大类别分数，也不要假设存在 objectness 通道。当前 decoded 输出是：

```text
4 个 bbox 通道 + 1 个类别分数通道 = 5
```

逐 anchor 后处理流程：

1. 遍历 `i = 0 ... 33599`
2. 取 `score = output[0, 4, i]`
3. 如果 `score < conf_thres`，丢弃该候选框
4. 将 `cx, cy, w, h` 转成 `x1, y1, x2, y2`
5. 当前 letterbox 为 no-op，坐标仍是 `640 x 640` 模型输入坐标
6. 将坐标按 `700 / 640` 放大，还原到 `700 x 700` ROI 坐标
7. 如果需要画回 `1920 x 1080` 原帧，则加回 ROI 左上角偏移 `crop_x=565, crop_y=110`
8. 将还原后的坐标 clamp 到目标图范围
9. 对剩余框执行 NMS
10. 输出最终检测结果

坐标格式转换：

```text
x1 = cx - w / 2
y1 = cy - h / 2
x2 = cx + w / 2
y2 = cy + h / 2
```

letterbox 坐标还原到模型输入图：

```text
x1 = (x1 - pad_x) / letterbox_gain
y1 = (y1 - pad_y) / letterbox_gain
x2 = (x2 - pad_x) / letterbox_gain
y2 = (y2 - pad_y) / letterbox_gain
```

当前 resize 后的 `640 x 640` 输入下，letterbox 还原等价于：

```text
x1, y1, x2, y2 保持不变
```

模型输入坐标还原到 `700 x 700` ROI 坐标：

```text
roi_x1 = input_x1 * 700 / 640
roi_y1 = input_y1 * 700 / 640
roi_x2 = input_x2 * 700 / 640
roi_y2 = input_y2 * 700 / 640
```

如果最终结果需要映射回原始 `1920 x 1080` 帧，再加回 ROI 左上角偏移：

```text
orig_x1 = roi_x1 + crop_x
orig_y1 = roi_y1 + crop_y
orig_x2 = roi_x2 + crop_x
orig_y2 = roi_y2 + crop_y
```

其中当前固定为：

```text
crop_x = 565
crop_y = 110
```

坐标裁剪。如果结果用于模型输入图，范围是 `640 x 640`：

```text
x1 = clamp(x1, 0, 639)
y1 = clamp(y1, 0, 639)
x2 = clamp(x2, 0, 639)
y2 = clamp(y2, 0, 639)
```

如果结果用于 `700 x 700` ROI，范围是：

```text
x1 = clamp(x1, 0, 699)
y1 = clamp(y1, 0, 699)
x2 = clamp(x2, 0, 699)
y2 = clamp(y2, 0, 699)
```

如果结果用于原始 `1920 x 1080` 帧，范围是：

```text
x1 = clamp(x1, 0, original_width  - 1)
y1 = clamp(y1, 0, original_height - 1)
x2 = clamp(x2, 0, original_width  - 1)
y2 = clamp(y2, 0, original_height - 1)
```

NMS 参数要与 PyTorch 推理侧保持一致：

```text
conf_thres = 0.25
iou_thres  = 0.35
```

当前只有 1 类，可以直接对所有候选框做一次 NMS。最终结果格式建议统一为：

```text
class_id confidence x1 y1 x2 y2
```

其中：

```text
class_id = 0
class_name = contamination
```

### 7.2 后处理伪代码

```text
candidates = []

for i in range(33600):
    score = output[0, 4, i]
    if score < conf_thres:
        continue

    cx = output[0, 0, i]
    cy = output[0, 1, i]
    w  = output[0, 2, i]
    h  = output[0, 3, i]

    x1 = cx - w / 2
    y1 = cy - h / 2
    x2 = cx + w / 2
    y2 = cy + h / 2

    x1 = (x1 - pad_x) / letterbox_gain
    y1 = (y1 - pad_y) / letterbox_gain
    x2 = (x2 - pad_x) / letterbox_gain
    y2 = (y2 - pad_y) / letterbox_gain

    # 模型输入 640x640 坐标还原到 700x700 ROI 坐标。
    x1 = x1 * 700 / 640
    y1 = y1 * 700 / 640
    x2 = x2 * 700 / 640
    y2 = y2 * 700 / 640

    # 如果需要画回 1920x1080 原帧，则加回 ROI 左上角偏移。
    x1 = x1 + crop_x
    y1 = y1 + crop_y
    x2 = x2 + crop_x
    y2 = y2 + crop_y

    x1 = clamp(x1, 0, frame_width - 1)
    y1 = clamp(y1, 0, frame_height - 1)
    x2 = clamp(x2, 0, frame_width - 1)
    y2 = clamp(y2, 0, frame_height - 1)

    candidates.append([x1, y1, x2, y2, score, 0])

results = nms(candidates, iou_thres)
```

### 7.3 需要特别避免的错误

- 不要把输出当成 `[1, 84, 8400]`，本模型不是 COCO 80 类，也不是默认 P3/P4/P5。
- 不要使用 `8400` 个 anchor，本模型 P2/P3/P4 一共是 `33600` 个 anchor。
- 不要额外乘 objectness，当前 decoded 输出没有 objectness 通道。
- 不要在 `[1, 5, 33600]` 输出上再做 DFL decode，DFL decode 已经在导出的 ONNX 图内完成。
- 不要忘记 letterbox 坐标还原，否则框会相对原图发生偏移或缩放错误。
- 如果要把结果画回 `1920 x 1080` 原帧，不要忘记先按 `700/640` 还原到 ROI 坐标，再加回 ROI 偏移 `crop_x=565, crop_y=110`。

## 8. 如果导出的是真正 non-decode raw head

如果后续改成真正不含 DFL decode 的 raw 输出，输出就不再是 `[1, 5, 33600]`。

raw 输出应为 3 个 tensor：

```text
[1, 65, 160, 160]
[1, 65, 80, 80]
[1, 65, 40, 40]
```

或被某些转换工具合并为：

```text
[1, 65, 33600]
```

这种情况下后处理必须额外实现：

1. 按 P2/P3/P4 拆分 anchors
2. 对前 64 通道做 DFL softmax
3. 使用 `reg_max=16` 投影得到 `l,t,r,b`
4. 结合 anchor point 和 stride 解码 bbox
5. 对分类通道做 sigmoid
6. 再做 conf 过滤和 NMS

当前仓库的标准 Ultralytics ONNX 导出不建议按这个 raw 逻辑处理，除非你明确改了导出图。

### 8.2 RKNN INT8 输出注意事项

INT8 量化转换成功时，RKNN-Toolkit2 可能打印：

```text
W build: The default input dtype of 'images' is changed from 'float32' to 'int8'
W build: The default output dtype of 'raw_p2' is changed from 'float32' to 'int8'
W build: The default output dtype of 'raw_p3' is changed from 'float32' to 'int8'
W build: The default output dtype of 'raw_p4' is changed from 'float32' to 'int8'
```

这表示板端 Runtime API 拿到的 `raw_p2/raw_p3/raw_p4` 默认可能是 int8 输出，不是 float32。

部署侧后处理前必须先处理量化尺度：

1. 查询 RKNN output tensor 的 `scale` 和 `zero_point`
2. 将 int8 raw 输出反量化为 float
3. 再对反量化后的 float raw logits 做 DFL decode、分类 sigmoid、bbox decode 和 NMS

反量化公式：

```text
float_value = (int8_value - zero_point) * scale
```

如果后处理直接把 int8 数值当 float 使用，会导致：

```text
分类分数错误
DFL 分布错误
bbox 解码错误
最终检测框不可信
```

### 8.3 raw-head 后处理顺序

RKNN raw-head 输出的完整后处理顺序应为：

1. 读取 `raw_p2/raw_p3/raw_p4`
2. 如果输出 dtype 是 int8，先按每个输出 tensor 的量化参数反量化
3. 对每层输出 reshape：

```text
raw_p2: [1, 65, 160, 160] -> [1, 65, 25600]
raw_p3: [1, 65, 80, 80]   -> [1, 65, 6400]
raw_p4: [1, 65, 40, 40]   -> [1, 65, 1600]
```

4. 按 anchor 维度拼接：

```text
[1, 65, 33600]
```

5. 前 64 通道按 `4 x reg_max` 拆成 bbox 分布
6. 对每个方向的 16 个 bin 做 softmax
7. 用 `[0, 1, ..., 15]` 投影得到 `l,t,r,b`
8. 使用 P2/P3/P4 对应 anchor point 和 stride `[4, 8, 16]` 解码 bbox
9. 对第 65 个通道做 sigmoid 得到 `class0_score`
10. 使用 `conf_thres = 0.25` 过滤
11. 当前 letterbox 为 no-op，bbox 保持在 `640 x 640` 模型输入坐标
12. 按 `700 / 640` 将 bbox 还原到 `700 x 700` ROI 坐标
13. 如果要画回 `1920 x 1080` 原帧，则加回 ROI 左上角偏移：

```text
crop_x = 565
crop_y = 110
```

14. 使用 `iou_thres = 0.35` 做 NMS

## 9. 推理侧必须保持一致的参数


| 项目                       | 训练侧              | 推理/部署侧          |
| ------------------------ | ---------------- | --------------- |
| 输入尺寸                     | `640`            | `640`           |
| 原始帧预处理                   | 固定裁剪 `700 x 700` 后 resize 到 `640 x 640` | 固定裁剪 `700 x 700` 后 resize 到 `640 x 640` |
| 固定圆心                      | `x=885.0, y=430.0` | `x=885.0, y=430.0` |
| ROI 左上角                    | `x=565, y=110`  | `x=565, y=110` |
| ROI 尺寸 / 模型输入              | `700 -> 640`     | `700 -> 640`    |
| 类别数                      | `1`              | `1`             |
| 类别名                      | `contamination`  | `contamination` |
| 检测层                      | P2/P3/P4         | P2/P3/P4        |
| stride                   | `[4, 8, 16]`     | `[4, 8, 16]`    |
| anchors 总数               | `33600`          | `33600`         |
| PyTorch NMS conf         | -                | `0.25`          |
| PyTorch NMS iou          | -                | `0.35`          |
| ONNX/RKNN decoded output | -                | `[1, 5, 33600]` |
| raw head output          | `[B,65,H,W] * 3` | 仅 raw 导出时使用     |


## 10. 常见错误判断

如果后处理程序期望的是 YOLOv8 默认 P3/P4/P5 输出：

```text
8400 = 80*80 + 40*40 + 20*20
```

那就是错的。

本模型是 P2/P3/P4：

```text
33600 = 160*160 + 80*80 + 40*40
```

如果后处理程序期望类别数是 80：

```text
[1, 84, 33600]
```

那也是错的。

本模型只有 1 类，decoded 输出应是：

```text
[1, 5, 33600]
```

如果拿到的是：

```text
[1, 65, 33600]
```

说明这是 raw head，不是 decoded output，需要做 DFL decode。

## RKNN parity 工具链（ONNX Python ↔ C++ RKNN）

与 `check/onnx_infer.py` / `tools/rknn_infer` 对齐时，下列参数**必须锁定**：

| 参数 | 值 |
|------|-----|
| input_width / input_height | 640 / 640 |
| 固定裁剪 | ROI 700×700 @ (565, 110) |
| letterbox | 默认关闭 |
| num_classes | 1 |
| reg_max | 16 |
| strides | 4, 8, 16 |
| raw_channel_order | **box_first** |
| conf_threshold（调试） | 0.25 |
| nms_threshold | 0.35 |
| score | logits + sigmoid |
| decode | DFL → dist2bbox xywh → × stride |
| 输出坐标 | xyxy（全图，ROI 还原 ×700/640） |

**三阶段 dump：**

1. `input.bin` — float32 NCHW RGB/255（ONNX 路径；RKNN 可能为 UINT8 NHWC，需分别记录 manifest）
2. `raw.bin` — 拼接后 `[65, 33600]` float32
3. `boxes.bin` — 全图 xyxy + score

```bash
# Python 参考
python check/infer.py det --model det_raw_head.onnx --source frame.jpg \
  --dump-dir runs/dump_py --parity-stage full

# C++ RKNN（板端或交叉编译）
./rknn_infer --model det_raw_head.rknn --source frame.jpg \
  --dump-dir runs/dump_cpp --parity-stage full

python check/compare.py parity runs/dump_py runs/dump_cpp --raw-atol 0.01
```

详见 `tools/rknn_infer/README.md`、`docs/ONNX_DET_POSTPROCESS_TROUBLESHOOTING.md`。

## ADDED Requirements

### Requirement: Inbound process parameter command envelope
Frames with `type` equal to `command.send_process_param` SHALL use the unified WebSocket JSON envelope (`v`, `type`, `id`, `ts`, `payload`). The `payload` object SHALL contain the process-parameter content in a shape the device can map to the same persistence model used for MQTT `ONE_PROCESS_DATA` (`ProcessParametersData` and its MQTT message wrapper fields as implemented in the app).

#### Scenario: Command frame structure
- **WHEN** the server sends a `command.send_process_param` message
- **THEN** the frame MUST include top-level `v`, `type`, `id`, `ts`, and object `payload`, and MUST NOT place process-parameter fields outside `payload`

### Requirement: Outbound process parameter acknowledgement
After the device completes handling of an inbound `command.send_process_param` frame (including persistence or application-defined handling that finishes the request), the device SHALL send a WebSocket frame with `type` `command.send_process_param_ack`. The outbound frame SHALL use a **new** top-level `id` generated by the device for that outbound message (per outbound message identity rules elsewhere in this capability). The outbound `payload` SHALL be a JSON object containing:
- string field `request_id` whose value equals the top-level `id` of the inbound `command.send_process_param` frame
- numeric field `code` (`200` for success, `500` for failure)
- string field `message` (human-readable result; empty string allowed)

#### Scenario: Ack uses new message id
- **WHEN** the device receives `command.send_process_param` with top-level `id` `server-msg-1`
- **THEN** the device MUST send `command.send_process_param_ack` whose top-level `id` is newly generated for that ack and MUST NOT reuse `server-msg-1` as the outbound `id`

#### Scenario: Ack payload carries result details
- **WHEN** the device sends `command.send_process_param_ack` in response to an inbound command whose top-level `id` is `server-msg-1`
- **THEN** `payload` MUST include `request_id` equal to `server-msg-1`, a numeric `code`, and string `message`

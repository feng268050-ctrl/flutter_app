# ek3562 DTS drop (pending vendor)

Do **not** add `ek3562` to `board/rk356x-fit-boards.txt` until a real board
`.dts` exists — `make build-kernel` would look for `ek3562.dtb` and fail.

When the vendor delivers the tree, follow the same layout as **ynh960** (see
[`README.md`](README.md)):

1. Land `ek3562.dts` + `customer_board_ek3562.dtsi` (or single board dtsi) under
   **`overlay/kernel/rockchip/`** — not only in `linux-sdk/`.
2. Include RK3562 SoC dtsi from the SDK kernel; **do not** include ynh960 /
   `own-gpio` / `gpio_innohi` / Innohi ParamUpdate fragments.
3. GPU is the same Mali as RK3566 — reuse existing Mali/Weston userspace; only
   DT display/VOP nodes come from the vendor.
4. Append `ek3562` to `board/rk356x-fit-boards.txt`, clear OEM pack
   `compat.fit_dt: pending`.
5. `make apply-overlay` then `FORCE_KERNEL_IMAGE=1 make build-kernel` if new
   SoC Kconfig/drivers were merged; otherwise plain `make build-kernel` after
   DTS-only.

U-Boot must `bootm <addr>#ek3562` (or factory env). Innohi `boot_fit` default
conf is still `ynh960`.

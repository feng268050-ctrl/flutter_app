## Why

设备首次使用时若未连接 WiFi，用户可能无法完成配网或云端能力受限；需要在合适的时机主动引导连接 WiFi，并在用户完成**首次** WiFi 连接后记住该状态，避免在后续「忘记网络」等场景下反复打扰。

## What Changes

- 引入** WiFi 初始化完成**的持久化开关（布尔）：表示「至少已成功完成过一次 WiFi 连接/初始化」。
- **仅当设备未连接 WiFi** 时，在应用进入合适的主流程节点展示**弹窗**，提示用户连接 WiFi；确认操作跳转到系统 **WiFi 设置**（或应用内既有 WiFi 配置入口，以实现为准）。
- 若在上述检查点**已经**连接 WiFi，则**立即**将开关置为真并持久化，**不展示**弹窗。
- 若在未连接状态下之后**首次**连上 WiFi，同样将开关置为真并持久化；此后**不再**展示该弹窗，即使用户之后断开或忘记网络。
- 不将「仅关闭弹窗未连接」视为完成初始化（除非产品另行规定；当前以实现「首次连接成功」为准）。

## Capabilities

### New Capabilities

- `wifi-initialization-onboarding`: 首次 WiFi 引导：**仅未连 WiFi** 时提醒弹窗与确认跳转 WiFi 设置；**已连 WiFi 则立即**写入完成标记；从未连接变为已连接同样写入；之后不再提醒（含忘记网络）。

### Modified Capabilities

- （无）本变更为新增引导与持久化状态，不修改现有 WiFi 特权连接、密码对话框等规范的既有需求语义。

## Impact

- **应用层**：启动或主界面展示逻辑、对话框 UI、字符串与主题资源。
- **状态存储**：SharedPreferences / DataStore 等本地持久化（与项目现有偏好存储方式一致）。
- **系统集成**：跳转 `Settings.ACTION_WIFI_SETTINGS` 或等价 Intent；可复用现有 `WifiActivity` / `WifiStatusUtils` / `NetworkStatusUtil` 等。
- **测试**：覆盖「未初始化 + 已连接 → 立即写标记、无弹窗」「未初始化 + 未连接 → 弹窗 → 连上后写标记」、标记写入后不再弹窗、忘记网络后仍不弹窗。
